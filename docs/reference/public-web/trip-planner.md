## Private account itineraries — separate frontend candidate

Added /plan/saved against Admin's frozen /api/v1/me/itineraries contract. This is a separate private collection with owner-session checks, CSRF mutations, explicit create/copy/save, paginated list, full versioned update, confirmed versioned delete and comparison before retrying stale writes. New names suggest Untitled trip; stops retain the exact89 canonical slugs, max20 unique ordered stops and1–14 nights. The existing planner editor is reused in memory-only account mode. No private account itinerary is written into browser draft storage. Guest copying is explicit and leaves the original local draft untouched. Account and planner navigation link to saved trips.

Superseding create contract: UUIDv4 Idempotency-Key and exact normalized payload are retained in memory for the current save operation. A lost response locks editing until explicit Retry original save; retry reuses both, then reads the returned ID's current state. Replaying creation never treats its old envelope as current state; a later deleted trip is reported unavailable, never recreated. A deliberate new copy gets a new key. Pending request recovery is limited to the current page; beforeunload warns about unsaved work, and no private payload is persisted to local storage. Backend owns lifetime key retention and atomicity; frontend mocks do not prove it.

401/419 and detected identity changes clear private list/editor state; mutations check identity before and after the request, late results are fenced. Network/validation/conflict failures keep edits; transient identity-read errors do not erase work. Confirmed conflict requires saved-version comparison and an explicit use-saved or keep-edits choice before another write. Reads and writes use no-store; route is noindex.

Local production build/TypeScript, lint and focused browser cases cover explicit copy/create/update/delete, local/account storage separation, ambiguous create replay loading newer state, replay after deletion, version conflicts/manual resolution, account-change denial and320px layout. Existing local planner and account/coverage cases pass. Backend implementation, independent exact API integration and deployment are still pending.
